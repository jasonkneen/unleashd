# Attempt diagnostics replacement

Before: a queued turn is reported by `TurnRunner`, queued again through `runtime-observer`, serialized into JSONL, replayed into a mutable map, exposed through a history endpoint, then polled and shape-guessed by the browser. Rotation can discard the creation event while keeping later events, so replay even fabricates a partial attempt.

After: `TurnRunner` remains the execution and joined-drain owner. One shared Zod attempt snapshot and outcome contract describes queued, active, and finished attempts; missing provider activity remains absent, and old `timeout` remains a distinct legacy cause. The observer orders asynchronous writes to one SQLite attempt/event store. The store owns durable snapshots, event history, indexed latest-by-conversation reads, and bounded retention. Only a transition write changes an attempt. Detail loading and patches carry the current snapshot; the existing history endpoint still provides `includeEvents`.

Boundary: raw v1 JSONL is parsed once during import into the new database on a copy or first boot; malformed lines are skipped with a count, and original files remain untouched for recovery. Runtime writes are canonical. Native storage accepts typed JSON at the NAPI boundary and indexes identity/state columns. Readers parse with the shared schema at the application edge.

Dispatch: `queued`, `starting`, `running`, `stopping`, `activity`, `session`, `terminal`, and `recovered` each update the one snapshot and append its typed event. The runner may assume this path does not own process settlement. The UI dispatches presentation by attempt state and typed terminal cause.

Deletion: JSONL append/repair/rotation/reload and in-memory full scans; duplicate client `TurnAttemptSnapshotLike` and response-shape guessing; per-thread diagnostics timer/cancellation loop. Preserve queue-message and provider-session correlation, exact timeout causes, separate bridge/progress clocks, privacy-safe activity, async observation order, restart interruption, history/events, and joined drain. Verify these at the native store, legacy import, runtime, HTTP, client detail/patch, and recovery boundaries.

Implemented store: `<data-dir>/observability/turn-attempts.sqlite` contains indexed attempt snapshots and append-ordered events. One NAPI handle retains a SQLite connection. Snapshot and event commit together; a retained terminal attempt cap of 10,000 and event cap of 200,000 bound history. Active attempts are never pruned. The legacy `turn-attempts.jsonl` and `.1`–`.4` files are read once in oldest-first order; rows and the import marker commit in one transaction. The importer leaves every source byte, including malformed or partial lines, untouched, reports skipped lines, and rejects boot when a nonempty history has no readable event. A later boot interrupts only old-boot active attempts with `server_restart`.

The authenticated `GET /api/conversations/:id/diagnostics` response still carries `serverBootId`, `latestAttempt`, `attempts`, and optional `recentEvents` when `includeEvents=true`. The current attempt also arrives in `GET /api/conversations/:id` and `t: 'attempt'` patches. A missing field from a backend still reloading parses as `null` until that backend is ready. Open desktop/mobile conversations and the Buddy worker detail projection read the same attempt contract.
