# Typed transcript content slice

The transcript message remains the ordered record. Its sole content authority is a tagged `body`: either `{t:'text',text}` or `{t:'parts',parts}`. Parts carry ordered text, tool calls, questions, Buddy Builder receipts, worker links, and swarm launches. Provider and historical adapters produce this one contract before rendering. A typed tool part retains raw name/input; one client formatter owns summaries, while launch classification occurs once at ingress. Old HTTP pages and WS frames with `{content}` are upgraded at schema/wire ingress during the backend reload window. No renderer sniffs historical markers. Live WS parts use the existing conversation stream order and overlay record, so settle cannot duplicate them.

Delete the live `formatToolUse` marker/text writer, Rust's duplicate tool-summary and receipt marker writers, client marker and emoji-tool scanners, and retired team-configuration writer/schema. Retain only historical marker suppression/decoding at ingress, restricted to generated assistant output; owner-authored channel posts remain literal. Keep chat and channel containers distinct; each consumes the same typed part contract where transcripts are displayed.

Invariants: provider order and tool identity; Codex completion-only shell suppression; failed results do not yield receipts; question data is parsed once; old transcripts remain readable; worker links require valid conversation IDs; copy/export and memory review serialize parts deliberately; a rewritten ingest history replaces the overlay without duplication. Boundary tests will replay live and saved events and exercise the rendered shared transcript row. A baseline/after screenshot comparison will cover visible chat and thread output.

Evidence: the native formats/tail tests cover provider order, append/full equivalence, and old-checkpoint replacement; server content-boundary tests cover old HTTP/WS frames, warm-store parity, hidden-marker suppression, and reviewer input. Client grouping, channel, Builder, DM, and loading-race tests exercise the rendered contracts.
